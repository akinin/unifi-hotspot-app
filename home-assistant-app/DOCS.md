# UniFi Hotspot

Приложение создаёт гостевой портал UniFi с авторизацией по SMS. Код можно
отправлять через Wiren Board или USB-модем. Административный интерфейс открыт
через Ingress и доступен только администраторам Home Assistant.

## Быстрый запуск

1. Откройте вкладку **Конфигурация** приложения.
2. В разделе **Канал SMS** выберите:
   - `mqtt` — Wiren Board;
   - `mmcli` — USB-модем.
3. Заполните параметры выбранного транспорта.
4. Оставьте **UniFi → Тестовый режим** включённым.
5. Сохраните настройки и перезапустите приложение.
6. Откройте веб-интерфейс приложения и отправьте тестовое SMS во вкладке
   **WB** или **USB**.
7. После проверки SMS настройте UniFi и только затем отключайте тестовый режим.

Настройки сгруппированы по назначению. Неиспользуемые разделы можно оставить со
значениями по умолчанию.

## Разделы конфигурации

### Безопасность и API

- **Токен HTTP API** защищает методы отправки SMS и OTP. Используйте длинное
  случайное значение и не передавайте его в URL.
- **Секрет OTP** можно оставить пустым. При первом запуске приложение создаст
  стойкий секрет и сохранит его в `/data/app_secret`.

Пустой API-токен безопасно отключает защищённые HTTP-методы.

### Канал SMS

**Основной транспорт** определяет, как портал, OTP и HTTP API отправляют SMS:

- `mqtt` — через Wiren Board;
- `mmcli` — через ModemManager и USB-модем.

Тестовая отправка во вкладках **WB** и **USB** всегда использует транспорт
выбранной вкладки, независимо от основного транспорта.

### Wiren Board

Рекомендуется отдельный MQTT-пользователь с доступом только к следующим
топикам:

```text
write /devices/sms_sender/controls/send/on
read  /devices/sms_sender/controls/last_sent_time
read  /devices/sms_sender/controls/last_message_text
read  /devices/sms_sender/controls/last_recipient_number
read  /devices/sms_sender/controls/last_result
```

Для текущей установки используются защищённый listener `10.10.100.5:1884` и
топик `/devices/sms_sender/controls/send/on`. Анонимный доступ должен оставаться
выключенным.

#### Обязательный сценарий WB

На Wiren Board обязательно должен быть установлен файл
[`send_sms.js`](../wirenboard/send_sms.js) по адресу:

```text
/etc/wb-rules/send_sms.js
```

Он создаёт виртуальное устройство **Отправка SMS**, принимает команду из MQTT и
передаёт её в `Notify.sendSMS()`.

Проверка на Wiren Board:

```bash
systemctl is-active wb-rules mosquitto
journalctl -u wb-rules -n 100 --no-pager
```

Не используйте открытый MQTT-порт в недоверенной сети. Пароль MQTT храните
только в конфигурации приложения и менеджере секретов.

### USB-модем

1. Подключите совместимый модем к машине Home Assistant.
2. Выберите транспорт `mmcli`.
3. Оставьте **ID модема** равным `any` для автоматического выбора или укажите
   конкретный ID из `mmcli -L`.
4. Перезапустите приложение и проверьте оператора, регистрацию и сигнал во
   вкладке **USB**.

### UniFi Network

- **Тестовый режим** блокирует все изменяющие действия над клиентами.
- **Адрес контроллера** — локальный URL UniFi Network.
- **API-ключ** — предпочтительный способ авторизации.
- **Локальный пользователь и пароль** нужны только если API-ключ недоступен.
- **Сайт** обычно имеет значение `default`.
- **Проверка TLS** должна быть включена после установки доверенного сертификата.
- **Гостевой доступ** в конфигурации хранится в минутах; в веб-интерфейсе его
  удобнее менять в днях.

Порядок безопасного подключения:

1. Заполните адрес и учётные данные.
2. Сохраните включённый тестовый режим.
3. Убедитесь, что веб-интерфейс показывает контроллер и способ авторизации.
4. Проверьте портал на тестовом клиенте.
5. Отключите тестовый режим только перед контролируемой проверкой авторизации.

### Оформление портала

В конфигурации задаются текст приветствия, цвет фона и исходный размер логотипа.
Загрузка логотипа и интерактивный предпросмотр доступны в веб-интерфейсе:

1. Откройте **Hotspot → Просмотр**.
2. Измените логотип, фон, текст или размер.
3. Проверьте мобильный и широкий режим.
4. Нажмите **Сохранить**.

Предпросмотр изолирован и не отправляет SMS, не создаёт OTP и не меняет доступ
клиента.

### Telegram

Раздел предназначен для необязательных служебных уведомлений. Если Telegram не
используется, оставьте токен и ID чата пустыми.

### Одноразовые коды

- **Срок действия** — сколько секунд код остаётся действительным.
- **Длина** — количество цифр в коде.
- **Повторная отправка** — минимальная пауза между SMS.
- **Максимум попыток** — защита от перебора.

Начальные значения подходят для тестирования: код из 6 цифр, срок 5 минут,
повтор через 60 секунд и не более 5 попыток.

## Веб-интерфейс

- **Hotspot** — состояние UniFi, активные гости, архив и оформление портала.
- **WB** — тестовая SMS, состояние MQTT, обязательный сценарий и журнал.
- **USB** — тестовая SMS, модель модема, оператор, регистрация и сигнал.

## Сетевые адреса

- Административный интерфейс: кнопка **Открыть веб-интерфейс** в Home Assistant.
- HTTP API: `http://HOME_ASSISTANT_IP:18088`.
- Тестовый портал: `http://HOME_ASSISTANT_IP:18880`.

Проверка состояния API:

```bash
curl http://HOME_ASSISTANT_IP:18088/health
```

## Переход со старого LXC

1. Сделайте резервную копию приложения.
2. Проверьте отправку через WB или USB.
3. Проверьте выдачу и проверку OTP.
4. Проверьте тестового клиента при включённом тестовом режиме UniFi.
5. Кратковременно отключите тестовый режим и проверьте авторизацию одного
   клиента.
6. Только после этого измените адрес captive portal в UniFi.
7. Старый LXC остановите, но не удаляйте до завершения периода наблюдения.

## Резервное копирование

База, журнал, сгенерированный OTP-секрет, загруженный логотип и изменения
портала находятся в `/data` и включаются в резервную копию приложения Home
Assistant. После восстановления проверьте MQTT, UniFi и отправку тестового SMS.
